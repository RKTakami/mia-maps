## The map can read from its own store

Follows v0.1.15-beta, which was published mid-session and then left behind by several
hours of work. This adds the 16 commits that came after it.

> ⚠️ **Known: this crashes on Windows.** Reported on 2026-07-30, cause not yet found. No
> crash report has been collected, so there is no diagnosis to give — only that it
> happens. **macOS users should update; Windows users should not, until this is
> understood.** v0.1.15-beta has the same risk: nothing in either release has ever been
> run on Windows, and every Windows native is cross-compiled and compile-verified only.

Tested on macOS (Apple Silicon) against Mine In Abyss on 1.21.11, on a live server with
Sodium and Iris.

---

### The 2D map can draw from the mia-loddy store

Settings → **"Map Source"** switches between the Voxy engine and this mod's own store, so
the two can be compared on the same view. Off by default, and it falls back to Voxy
wherever the store cannot serve a tile, so turning it on cannot blank the map. The map
screen shows which source drew the frame.

This matters beyond the feature: `compose` no longer needs a Voxy engine in store mode,
which makes the **Voxy dependency optional rather than structural**. Two steps remain
before it can be dropped entirely — comparing the two sources for fidelity, then
defaulting to the store.

Works at every zoom. The two stores are keyed in different coordinate spaces — the map in
Abyss-shifted space, the store in vanilla chunk space — and the Abyss lifts each sector by
480 blocks, which is not a whole number of sections above level 0. A tile that starts
part-way up a section is therefore stitched from two. The offset is always a whole number
of cells, so that is a copy rather than a resample.

### Import and export between the stores

Two buttons in Map Settings. Import exists because the store only knows terrain walked
since indexing was switched on, while Voxy may have been accumulating for months. Export
exists because the point of the store is to feed renderers that read Voxy.

Both walk a bounded region around the player — roughly 768 blocks — because neither store
can be enumerated. Terrain outside that is not transferred; run it again from elsewhere to
cover more.

**Export never overwrites.** It writes only sections Voxy does not already have, and it
takes two clicks. Voxy's database is live while this runs, and this mod's data is a
quarter-resolution reconstruction whose sector is ambiguous inside the Abyss overlap band —
filling gaps is defensible on that basis, replacing good data is not.

### Progress you can actually see

Transfers report to chat and on screen, not only to the log, with the store's section
total before and after — "sections written" cannot answer "did that do anything" when
indexing deduplicates by content hash.

A pair of brass gears turns while background work runs, and replaces the mouse pointer
while a transfer is in progress. The indicator lingers briefly past completion so a
one-second job registers as an event rather than a flicker; the work itself is not slowed.

### Renamed native

The LOD store's native library is now `mia_loddy` rather than `mia_lods`. The store
**directory** is deliberately unchanged: new installs use `.mia-loddy`, but an existing
`.mia-lods` keeps being used, because renaming it would orphan every section already
captured.

### Known limits

- **Crashes on Windows** (above).
- The world renderer submits every quad per frame; vertex buffers are the fix and are not
  in this release.
- 1-block passages in the 3D orbit view still need a close zoom — that path is still a
  dense grid and its ceiling is unchanged.
- Cave Maps above ~85% reads as mush on deep terrain.
- `config/voxy_mia_light_zones.json` containing `"hi"` throws on every boot.
